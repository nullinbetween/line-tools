# LINE 對話紀錄小工具——抽取、分割、歸檔，全程在瀏覽器裡完成

三個單一 HTML 工具，處理 LINE 匯出的純文字對話紀錄：

| 工具 | 做什麼 | 輸入 | 輸出 |
|---|---|---|---|
| [`date-extractor.html`](date-extractor.html) 日期抽取器 | 抽出指定日期範圍 | 多個 `.txt`，或含 txt 的 `.zip` | 單一 `.txt` |
| [`splitter.html`](splitter.html) 文件分割器 | 把長紀錄切成多段 | 一個 `.txt` 或 `.docx` | `.zip`（內含多個 `.txt`） |
| [`merger.html`](merger.html) 文件合併器 | 按月或按年歸檔 | 多個 `.txt`，或 `.zip` | `.zip`：`2024/2024-01.txt` … |

打開 HTML、把檔案拖進去、按按鈕。**你選的對話紀錄只在你自己的裝置上處理，不會上傳**——對話紀錄是一個人最私密的資料之一，整個設計就是從這點出發。

**線上 demo：**<https://nullinbetween.github.io/line-tools/>——可用範例對話試用；你拖進去的檔案只留在你的瀏覽器裡。

## 設計筆記——我們怎麼想的

LINE 匯出的是一個很長的文字檔：每天一行日期，底下是那天的訊息。大家想從裡面拿到三樣東西——**一段**（「只要二月」）、**分段**（小到能讀完，或能貼進有輸入上限的 AI 助手）、**歸檔**（每月一個檔）。三個工具各做一件。

| 決定 | 為什麼 | 我們接受的代價 |
|---|---|---|
| **全部在瀏覽器裡執行，每個工具一個 HTML** | 不用安裝、不用相信任何伺服器；下載到本機的副本沒有網路也能用。 | 受瀏覽器記憶體限制，所以有下方的上限。 |
| **以日期行為骨幹** | 找出「整行只有日期」的行（可帶星期，例如 `(Tue)`、`（二）`、`Tuesday`、`星期二`、`火曜日`），範圍、月份、安全的切點就都跟著出來。只認真正的星期名稱；日期後面接其他字（例如「2024/03/01休假」「2024/03/01 Monsoon」）就是訊息，不是日期行。 | 若某則訊息剛好是單獨一行日期，會被當成日期行（已寫明）。 |
| **以「哪一組是 4 位數」判斷年份位置** | 不同語系的匯出格式不同：`2024/01/30（二）` 與 `30/01/2024（二）`。寫死一種順序，另一種就壞。 | `x/y/YYYY` 一律視為日/月；月/日 寫法只有在日 > 12、不可能成立時才會被抓出來。 |
| **日期跨檔延續** | 長對話常分好幾個檔存，一天可能被切在中間。檔案依自然檔名順序處理（`part_2` 在 `part_10` 前），目前日期延續到下一個檔。 | 檔名順序必須等於時間順序。 |
| **盡量只在日與日之間切** | 每一段都能單獨閱讀。單一天本身超過上限時，在那一天的行與行之間切；只有單一行本身超過上限才會從行內切開。各段接回去與原文完全相同。 | 每段大小不一。 |
| **日期必須真的存在** | `2024/02/30`、`12/31/2024` 不能默默開啟新的一天。這類行保留為內容，並在結果中顯示數量。 | — |
| **同名檔：內容相同 → 只用一份；內容不同 → 停下來請你改名** | 默默丟掉一份會遺失資料；猜哪個在前會打亂順序。 | 有時需要你改檔名。 |
| **硬上限與解壓炸彈防護** | 單檔 50 MB、zip 100 MB、解壓後合計 200 MB；解壓超過上限立刻停止。分頁不該當掉，小 zip 也不該膨脹成好幾 GB。 | 非常大的壓縮檔需要先拆開。 |
| **不承諾匿名化** | 原本的流程裡，這些工具搭配另一個去識別化工具。要做好很難，做一半反而給人錯誤的安全感，所以本版不包含。 | 輸出的保護由你負責。 |
| **三個小工具共用核心** | 每個檔都能獨立使用（開一個 HTML 就好），所以核心刻意複製到三個檔裡——三份一旦不一致，測試就會失敗。 | 程式碼重複，靠測試保持一致。 |

## 教學

### 1. 從 LINE 匯出對話

iPhone（選單名稱依 LINE 版本可能不同）：打開聊天室 → 右上角 **≡** → **其他設定** → **傳送聊天記錄** → **儲存到檔案**。
會得到一個 `.txt`；照片和影片不包含在內。其他平台也有類似的「傳送／匯出聊天記錄」功能。把 `.txt` 移到電腦上。

手邊沒有對話？用 `examples/` 的虛構資料練習：`chat-part-001.txt` 和 `chat-part-002.txt` 是同一段對話分兩個檔存，2024-02-01 跨在兩檔之間。

### 2. 常見用法

**從長對話裡抽出一段時間**——`date-extractor.html`
1. 把 `.txt`（或含 txt 的 `.zip`）拖進框裡。摘要會顯示選了幾個檔、處理順序。
2. 以 `YYYYMMDD` 輸入範圍，例如 `20240201` → `20240204`（兩端都包含；`2024-02-01` 也可以）。
3. 按 **Extract**（工具介面是英文）。會下載 `line_extracted_20240201-20240204.txt`；結果會顯示找到的日期跨度、命中天數、輸出行數。

**把長對話在日與日之間切成多段**——`splitter.html`
1. 拖入一個 `.txt` 對話匯出檔。
2. 保持 **Split .txt by: Characters per file** 模式，設定大小（預設 3,500 字），保持勾選 **Cut at date lines**。
   這樣每一段都只在新的一天開始處切開。例外是單一天本身就超過設定大小：那一天會在訊息與訊息之間切開（單則訊息本身超過大小時才按長度切，不會切壞字元），結果訊息會寫出有幾天被這樣切。
3. 按 **Split**。會下載 `<前綴>_split.zip`，內含 `<前綴>_001.txt`、`<前綴>_002.txt`……

`.docx` 則是按頁切，不看日期：**Pages per file** 決定大小，頁面依 Word 存檔時記下的分頁（沒有分頁記號的檔案，例如 Google 文件匯出的，改用 **Characters per page**）。

**把對話按月歸檔**——`merger.html`
1. 拖入所有分段（或 `.zip`）。
2. 選 **One file per month**（或每年一檔、全部一個檔）。
3. 按 **Merge**。會下載 `merged.zip`，內含 `merged/2024/2024-01.txt`……；第一個日期行之前的內容（匯出檔頭）放在 `undated.txt`。

有問題時工具會直接說，不會自己猜：不存在的日期、同名檔、過大或加密的 zip、舊版 `.doc`。每則訊息都會指出是哪個檔、該怎麼處理。

## 限制

| | |
|---|---|
| 大小 | 單一 txt（或 zip 內單檔）與 `.docx` 50 MB；單一 zip 100 MB；一次處理解壓後合計 200 MB；zip 內最多 5,000 個項目；最多輸出 5,000 個檔 |
| zip | 只支援未壓縮或 deflate；**不支援加密 zip、ZIP64**；每個項目都會檢查 CRC |
| Word | 只支援 `.docx`（不支援 `.doc`）；受密碼保護的無法讀取 |
| 文字編碼 | UTF-8（含或不含 BOM）、含 BOM 的 UTF-16、Big5 |
| 瀏覽器 | 需要 `DecompressionStream('deflate-raw')`：Chrome／Edge 103+、Safari 16.4+、Firefox 113+ |

上限是每個檔案核心區塊開頭的 `LIMITS` 常數，可自行調整。更多見 [`ISSUES.md`](ISSUES.md)。

## 從個人工具到開源

它們原本是一個更大的個人工作流程裡的小幫手。公開時只保留三個通用工具，並且：

- 加上真正的日曆驗證（原版接受 2 月 31 日，合併器完全不檢查日）；
- 同名檔從「默默丟掉」改成「相同用一份、不同就停下」；
- 加上大小上限、ZIP64／加密偵測與串流式解壓炸彈防護（原本都沒有）；
- 三個工具統一文字解碼方式（合併器原本只認 UTF-8），錯誤訊息一律轉義；
- 依長度切割時，放得下的行保持完整，否則一定落在字元邊界（原本以 UTF-16 單位切，emoji 可能被切成「�」，訊息也會在行中被切開）、保留 `.docx` 裡的 tab（原本會被吃掉），並限制輸出檔數；
- 移除所有和去識別化工具有關的字樣，工具不會暗示自己有匿名化功能；
- 寫了虛構的示範對話，以及跑在這些資料上的測試（單元＋介面）。

## 製作方式

由作者設計，程式以 AI 程式助手協作寫成。開源準備是一個小型多代理流程：**Codex** 負責界定範圍並獨立驗收，**Claude** 負責依白名單複製、修正缺陷、撰寫測試與文件，最終決定由作者做出。
